# signon 1.1.0

Not published yet. Needs schema_guard_tokio 2.5.0.

Everything new is behind a feature that is off by default: a site that uses 1.0 as it is gets
the same build.

## New

- **Sign-in without a browser** (`signon::api`): for a service that is not a web page - an etcd
  server's Auth API first - over the same accounts and sessions. `api::sign_in` (the limits and
  SSO rules of `/login`, a session with no cookie), `identity`, `sign_out`, `add_account`, and
  role management.
- **Key-range permissions** (feature `permissions`): what a role may do - read, write or both -
  on a range of keys of a key space, etcd's ranges. `permissions::grant`, `revoke`, `of_role`,
  `of_user`, `permits`. With PostgreSQL not answering, a TOML file serves the mappings
  (`SIGNON_PERMISSIONS_FILE`).
- **LABAC, Leveled Attribute-Based Access Control** (feature `labac`):
  - Mapping rules turn what an identity provider says of a person - a SAML attribute, an OIDC
    `groups` claim, a SCIM group - into the account's subject: its ABAC groups, labels, the
    PostgreSQL role it works as, a ceiling. `labac::remap` runs them at each sign-in; the
    subject has a version every change moves.
  - Resources with ACL entries, and an evaluator: `Acl::level`, `allowed`, `reach`,
    `predicate`. An entry on resource `*` is for every resource of a kind.
  - Actions are levels: select 1, insert 2, update 3, soft delete 4, delete 5, ddl 6 - or a
    kind's own.
  - **Named levels**: a person's own level of a name (`sal`, the security access level, or any
    other), from a rule or set for one person (`set_level`). The person reaches what is at that
    level or lower.
  - **The approval scale**: the same levels read as what people decide - view 1, comment 2,
    recommend 3, approve 4, veto 5, override 6 (`labac::APPROVAL_ACTIONS`).
  - A token of the subject and its version (`issue`, `current`), and the page that hands a
    signed-in person its token (`GET /labac/token`), also for a lower level
    (`/labac/token?level=2`).
  - Optional: an OPA server's levels for a kind (feature `opa`), and the SQL half for
    PostgreSQL's row-level security (`apply_sql`, `enter_token`).
- **Service accounts** (feature `service-accounts`): a program's account mapped to the
  PostgreSQL role it uses, in by OAuth2 client credentials (`POST /token`), an API key or a
  PostgreSQL password.
- A page of the site's own for the redirect after a sign-in (`Config::with_signed_in_page`),
  for a browser where the redirect does not go through.

## Changed

- 1.1 adds fields to `saml::Assertion` (`groups`, `attributes`), `jwt::IdClaims` (`groups`) and
  `Config` (`signed_in_page`, `service`, `labac`). A caller that builds one of them by a struct
  literal, rather than receiving it or with `Config::new`, adds them.
